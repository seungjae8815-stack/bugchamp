# 밸런스 조정 절차

CLAUDE.md §6: **밸런스 수치는 오직 `packages/app/assets/data/*.json` 에서만 고친다.**
밸런싱 때문에 Dart 로직을 고쳐야 한다면 그건 설계 결함 신호다. 멈추고 사용자에게 말한다.

## 1. 무엇을 왜 바꾸는지 먼저 적는다

한 줄로 적는다. "순항 구간이 3대로 무너져서 타격 수를 6대로 되돌린다" 처럼
**유저 체감**으로 적는다. "hpAdaptExponent 를 0.88 로" 는 목표가 아니라 수단이다.

## 2. 현재 값을 잰다 (바꾸기 **전에**)

`packages/core_run` 안에서:

| 축 | 도구 |
|---|---|
| 젤리 수입·소비 | `dart run tool/jelly_sim.dart` |
| 성장 곡선·적응형 체력·타격 수 | `dart run tool/balance_sim.dart` |
| 제련 확률·기대 비용 | `dart run tool/forge_sim.dart` |
| 상한·int64 포화 | `dart run tool/clamp_check.dart` |

출력을 그대로 저장해 둔다. 이게 "전" 값이다. 안 재고 바꾸면 나중에 비교할 것이 없다.

## 3. JSON 을 고친다

- Dart 코드에 밸런스 상수를 넣지 않는다.
- 젤리 **소비** 금액은 5·10 단위로 떨어져야 한다(`roundJellyCost`). **수입은 반올림 금지** —
  반올림하면 하루 수입이 바뀌어 `jelly_sim` 결과가 통째로 어긋난다.
- 타이머를 바꿨으면 **즉시완료 젤리 실값**을 반드시 함께 본다(`pets.json → _timeComment`).
- 드롭 가중치를 바꿨으면 희귀 천장(`rarePityKills`)을 다시 계산한다.

## 4. 다시 재고 비교한다

같은 도구를 다시 돌린다. 결과는 **표**로 전후를 나란히 놓는다. 산문에 숫자를 섞지 않는다.
젤리는 하나의 숫자로 말하지 않는다 — 신규 / 중반 / 고인물 세 유형으로 나눈다.

## 5. 불변 조건을 대조한다

- 무한히 늘어나는 통로(분해·깜짝선물·광고 버프·미션)에 젤리를 붙이지 않았는가.
- 자동으로 굴러가는 보상(자동 방생)에 젤리를 넣지 않았는가.
- 적응형 체력 기준(§7) **밖**에 있어야 할 것을 안에 넣지 않았는가:
  종 패시브, 도감 영구 보너스, 버프, 탭 부스트, 장비, 공격속도, 월드 관문 배율.
- 도감 전 종 정복 보너스가 공격 +30% / 체력 +40% 를 넘지 않는가.
- 뽑기 등급 확률이 **야생보다 좋은가**. 돈을 내면 확률이 나빠지는 상품을 만들지 않는다.

## 6. 회귀 테스트

```
cd packages/core_run ; dart test
cd packages/app ; flutter test test/jelly_economy_test.dart test/data_test.dart
```

이 테스트들은 **수치가 아니라 구조 규칙**을 검사한다. 실패하면 값이 아니라 규칙을 어긴 것이다.
