# 장비 v2 — 옵션 다듬기 · 환생(별) 설계안 (2026-10-10, 사장님 검토용)

> 요청(실기 피드백): 옵션을 원하는 속성으로 바꾸기 · 바꾼 뒤 **기존/새 중 고르기** · 투자할수록 수치가 좋아지기 ·
> 장비에 별 등급(환생)을 달아 높을수록 수치가 높게.
> 확정된 방향(2026-10-10): 네 가지 모두 넣는다 · **화석으로도** 바꿀 수 있게(젤리 = 시간 절약) · 환생 재료 = **같은 부위 장비** ·
> 1.0.19 에 다른 수정과 함께.

## 0. 먼저 잰 것 — 장비가 세지면 얼마나 빨라지나

`balance_sim --tiers=4 --no-fairy --equip-scale=X` (지금 표는 X = 1.0 기준):

| 장비 세기 | 극한 최종 보스까지 |
|---|---|
| ×1.0 (지금) | **81일** |
| ×1.3 | 66일 |
| ×1.6 | 57일 |
| ×2.0 | 39일 |

장비는 적응형 위협 기준 **밖**이라(§2.7) 장비가 세지는 만큼 그대로 빨라진다. 기존/새 고르기만 넣어도 화석이 넉넉하면
(하루 약 2,000개) 일주일 안에 모든 줄이 그 등급 최대치 근처까지 간다 → 지금 시뮬 가정(상위 10% 롤 = 최대의 66%) 대비 약 ×1.5,
여기에 별까지 얹으면 ×2 근처 = **39일**. 그래서 이 설계의 핵심은 **다 키운 유저의 장비 세기 상한**이다.

**확정 목표(2026-10-10 사장님): 끝까지 투자한 유저 ≈ ×1.6 (81 → 약 57일).** 새 콘텐츠 = 더 강해지는 축(§2.4 "표를 다시 맞추지 않는다").
(제안은 ×1.3 · 66일이었다.)

## 1. 옵션 다듬기 (옛 재굴림 대체)

장비 한 줄(옵션 1개)을 고르고 다듬는다. 장착한 장비와 모루에서 막 나온 장비 둘 다.

| 항목 | 내용 |
|---|---|
| 결제 | **화석** 또는 **젤리 15**(지금과 같은 값). 화석 = 등급별 `100 × (등급+1)` (풀잎 100 · 호박 1,000 ≈ 접속 5시간 — 2026-10-10 사장님 ×5, 모자라면 젤리) |
| 종류 지정 | 원하는 옵션 종류를 고르면 수치만 굴린다 — 비용 **×3** (화석 600 · 젤리 45). 안 고르면 지금처럼 종류도 무작위 |
| 기존/새 고르기 | 굴린 뒤 **이전 값 / 새 값**을 나란히 보여 주고 고른다(비용은 이미 냈다) |
| 정성(최저값 상승) | 같은 줄을 다듬을 때마다 그 줄의 **정성 +1**(최대 10). 수치 굴림의 바닥 = 정성 × 4% (최대 40%). 정성은 그 장비에 남는다 |

- 수치 공식은 지금과 같다: `값 = 최소 + (최대 − 최소) × 굴림`, `굴림 = max(r⁴, 정성 × 0.04)`.
- 정성 바닥 40% 는 일부러 낮다 — 고르기가 이미 "좋은 것만 남기기"라, 바닥은 운이 아주 나쁜 사람을 받쳐 주는 정도면 된다.
- ⚠️ P2W: 젤리로만 되면 젤리를 쓸수록 능력치가 확실히 오르는 **스탯 판매**다(§2.6). 화석 경로가 같은 결과에 닿으므로
  젤리는 시간 절약이다(스킬 뽑기와 같은 구조). 화석 비용을 너무 올리면 사실상 젤리 전용이 된다 — 위 값은 하루 화석으로
  하루 10번 남짓.

## 2. 별 강화(옛 이름 환생 — 2026-10-10 사장님 개편)

| 항목 | 내용 |
|---|---|
| 별 | 장비마다 0~5성 |
| 재료 | 모루 결과 창의 **"별 재료"** 버튼 + **자동 제련에서 필터에 걸려 팔리던 장비가 먼저 별 재료로 쌓인다** — 같은 부위의 장착 장비에. 등급이 장착 장비 −1 이상 |
| 필요 수 | 1성 100개 · 2성 150 · 3성 200 · 4성 250 · 5성 300(누적 1,000개) — 다 모이면 **강화 시간** 2·4·8·16·24시간, 젤리로 당김(공방 등급업과 같은 값표) |
| 효과 | 그 장비 옵션 효과 × (1 + 0.04 × 별) — 5성 **+20%**. **회피는 제외**(예산 상한 · items.json 경고) |
| 교체 | 새 장비로 바꾸면 별의 **절반(내림)을 이어받는다**("환생") — 높은 등급이 나와도 별 때문에 못 바꾸는 일이 없게 |

- 별은 저장 값이 아니라 **효과 배율**로 붙는다(옵션 값은 그대로 등급 최대 이하) → 상한 자르기(`trimItemOptions`)·필터 표시를 안 건드린다.
- 같은 부위 · 높은 등급 장비는 귀해서(8부위 × 등급 확률) 5성이 오래 걸리는 목표가 된다. 지금은 팔기만 하던 장비에 쓸모가 생긴다.
- 별은 젤리로 사지 못한다.

## 3. 세기 예산 확인 (구현 뒤 시뮬로)

- 끝까지 투자: 모든 빌드 줄이 등급 최대의 약 90%(고르기 — 지금 가정 66% 의 ×1.37) × 별 5성 1.2 ≈ ×1.64 → **약 57일** 목표.
- `balance_sim` 에 다듬기·별을 넣은 장비 곡선을 추가해 확인한다(`--equip-scale` 은 대략치일 뿐). 57일보다 크게 빠르면
  별 배율(0.04)·정성 바닥(0.04)부터 낮춘다.

### 3.1 구현 뒤 측정(2026-10-10, `balance_sim --tiers=4 --no-fairy --gear-polish=q --gear-stars=n`)

첫날부터 그 상태라고 둔 **가장 빠른 경우**다.

| 조건 | 극한까지 |
|---|---|
| 지금 | 81일 |
| 별 5성만 | 71일 |
| 모든 빌드 줄 최대의 70% + 별 5성 | 54일 |
| 모든 빌드 줄 최대의 90% | 55일 |
| 90% + 별 5성 | 44일 |

- 호박 한 줄을 최대의 70% 이상(r⁴ ≥ 0.7)으로 만드는 데 평균 약 12번(화석 약 2,400), 90% 는 약 38번(약 7,600)이다.
  빌드 16줄 × 등급이 오를 때마다 정성은 새 장비에서 다시 시작하고(별만 절반 이어받음), 다듬기에 쓴 화석만큼 제련을 덜 돌린다.
  그래서 끝까지 투자한 유저도 대부분 "70% + 5성" 부근에서 오래 머문다 → 54일보다 느린 **약 57일 근처**로 본다.
- 출시 뒤 상위권 장비 분포(다듬기 횟수·별)를 보고, 90%+5성 유저가 흔하면 별 배율부터 낮춘다.

## 4. 저장 · 서버

- `EquipItem` 새 키: `st`(별) · `sx`(환생 재료 누적) · 옵션별 `p`(정성). 기본값이면 키 생략.
- ⚠️ 1.0.18 앱은 모르는 키를 **버린다**(`EquipItem.tryFromJson` 이 s/t/o 만 읽음) → `kSaveFeatureLevel` 21 + 서버가 feat 21 미만
  업로드에서 저장본의 별·정성을 되돌린다(`_restoreDroppedOptions` 에 "s/t/o 가 같으면 st/sx/p 복원" 분기). **서버 먼저 배포.**
- 서버는 items.json 을 읽지 않아 옵션 값 검사가 없다(기기 권위) — 별·정성도 기기 권위. 화석 감소는 서버가 검사하지 않는다(소비라 안전).
