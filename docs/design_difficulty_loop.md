# 난이도 회차(New Game+) 설계 — 2026-08-30 확정

> 스테이지 1000을 깨면 **스테이지 1로 돌아가되 난이도가 한 단계 오른다**.
> `쉬움 → 보통 → 어려움 → 극한`, 각 회차가 1~1000.

## 0. 왜 만드나 — 세 문제가 한 뿌리다

1. **스테이지에 상한이 없다.** `_stage++` 에 한계 검사가 없어 무한히 간다.
   실제로 스테이지 **1708** 유저가 있다(2026-08-30).
2. **후반이 무의미하다.** 시뮬 실측 **1200→1800 이 0.3일**. `hpAdaptMaxRatio`
   (3000)에 걸려 몬스터가 더 못 따라오는데 플레이어 전력은 계속 지수로 자란다.
3. **골드가 int64 를 넘겨 음수가 됐다.** 위 두 개의 증상이다 — 무한 진행 →
   지수 골드 → 오버플로. 상한(9e18)으로 급한 불은 껐지만 근본은 이 설계다.

회차로 끊으면 셋이 함께 풀린다. 경제가 회차당 유계가 되고, 1000 이 진짜
목표가 되며, 난이도 티어에 존재 이유가 생긴다.

## 1. 확정 사항

| 항목 | 결정 |
|---|---|
| 회차 구성 | 쉬움 / 보통 / 어려움 / 극한 — **각각 1~1000** |
| 전환 | 1000 클리어 후 **유저가 눌러서** 진입(자동 아님) |
| 이어지는 것 | 곤충 · 장비 · 도감 · **골드 · 재료 · 젤리** · 부화기/짝짓기 슬롯 |
| 초기화되는 것 | **스테이지 · 능력치 강화 · 캐릭터 레벨/경험치** (프레스티지) |
| 몬스터 | 회차마다 **위협도(공격)** 상승 + 목표 타격 수 소폭 상승 |
| 보상 | 몬스터와 같은 폭으로 상승 — 안 그러면 아무도 안 넘어간다 |
| 기존 1000 초과 유저 | **쉬움 1000 클리어**로 맞춘다. 초과분을 다음 회차로 환산하지 않는다 |
| 로드맵 챕터 난이도 라벨 | **지운다.** 챕터는 "구역 이름"(숲의 지배자 등)으로만 남는다 |

### ⚠️ "스테이지만 1 로"는 실패했다 (2026-08-30 실측으로 뒤집음)

처음 설계는 **스테이지만** 되돌리고 전력을 그대로 이어가는 것이었다.
이월을 모델링해 재보니 **2회차부터 이틀이면 끝났다**.

원인: 적응형 체력은 **"그 스테이지의 기본 체력"** 에 배율을 곱하는 구조다.
스테이지 1 은 기본 체력이 150 이라 상한(3000배)을 곱해도 20만이다 —
공격력이 1조든 100경이든 **똑같이 한 방**이다. 배율로는 못 고친다.

그래서 **다시 약해져야** 회차가 길어진다. 성장 축(강화·레벨)을 리셋하고
자산(곤충·장비·도감·재화)을 남긴다 — 방치형의 표준 프레스티지다.
남는 자산이 곧 "이번엔 훨씬 수월하다"는 성장 실감이다.

**실측(탭 유저 기준)**

```
회차 0(쉬움)   20일      회차 2(어려움) 19일
회차 1(보통)   12일      회차 3(극한)   23일     합계 74일
```

방치 유저는 33 / 18 / 25 / 39일 = **115일**.
1회차보다 2회차가 짧은 건 자산이 남기 때문이고, 3·4회차가 다시 길어지는 건
회차 배율이 자산 이득을 넘어서기 때문이다 — 의도한 모양이다.

### ⚠️ 보정 상한도 회차와 함께 열어야 한다

`hpAdaptMaxRatio`(3000)를 그대로 두면 **상한이 먼저 걸려** 목표 타격 수를
14 → 504 로 올려도 체력이 전 회차 동일했다. 회차 난이도가 통째로 무효였다.
상한에도 `tierHits(tier)` 를 곱한다.

그러면 극한 회차 월드보스가 int64 한계에 **딱 닿으므로**(여유 1.00배)
`kMaxMonsterHp`(4e18)로 자른다. 서식지·보스 **양쪽**에서 자른다 —
한쪽만 막으면 다른 쪽에서 넘친다.

### 왜 골드를 초기화하지 않나

회차당 1000스테이지면 경제가 유계라 int64 를 안 넘는다. 초기화하면 회차 전환이
**손실**로 느껴져 아무도 안 넘어간다. 이어지는 재화가 곧 "더 센 몬스터를 상대할
밑천"이다.

### 왜 초과분을 환산하지 않나

1708 → 보통 708 로 보내면 **그 유저만 보통 난이도를 700스테이지 건너뛴다**.
회차의 의미가 첫 유저부터 무너진다. 1000 클리어로 맞추고 다음 회차를 1부터.

### ⚠️ 체력에 배율을 곱하면 안 된다 (2026-08-30 실측으로 방향 수정)

처음엔 `tierHpMult = 10` 으로 몬스터 체력에 곱했다. **틀렸다.**
적응형 체력은 이미 "몇 대에 죽나"를 [hpAdaptTargetHits] 로 맞추고 있어서,
그 위에 곱하면 **타격 수가 그대로 배가 된다** — 실측 극한 회차에서
몬스터 하나에 **13,777대**였다. 지루한 스펀지지 어려운 게 아니다.

두 축으로 나눈다:

| 손잡이 | 값 | 하는 일 |
|---|---|---|
| `tierHitsMult` | 1.5 | 목표 타격 수 — 전투가 **조금** 길어진다 |
| `tierThreatMult` | 2.2 | 몬스터 공격 — **죽을 수 있게** 만든다 |
| `tierRewardMult` | 3.0 | 벌이 — 넘어갈 이유를 만든다 |

실측(스테이지 200):

```
타격 수   회차0 96대 → 회차3 299대   (예전 설계는 95,171대)
위협도    회차0 x1.0 → 회차3 x10.6
보상      회차0 x1   → 회차3 x27
```

**난이도는 때리는 횟수가 아니라 위험에서 나온다.** 그래야 체력·방어·회복과
장비 옵션이 실제 선택이 된다.

⚠️ 공격력이 아주 큰 후반에는 적응형 보정이 상한(`hpAdaptMaxRatio`)에 닿아
**회차가 체력을 못 바꾼다**. 그 구간의 난이도는 전적으로 위협도가 만든다.

## 2. 전환 안내 문구

⚠️ **수치를 쓰지 않는다**(사장님 지시 2026-08-30). "10배"처럼 적으면 밸런스를
조정할 때마다 문구가 거짓이 되고, 유저는 숫자보다 체감으로 판단한다.

> **보통 난이도로 진입합니다**
> 스테이지가 1로 돌아가지만 업그레이드·장비·곤충·재화는 그대로 이어집니다.
> 몬스터가 더욱 더 강력해집니다.

## 3. 진행도 표기

숫자만 보여주면(`401`) 어느 구간인지 모른다. **난이도 + 월드-월드내스테이지**:

```
쉬움 1-1   ·   보통 5-32   ·   극한 10-100
```

랭킹(진행도 축)도 같은 표기를 쓴다. **정렬은 `(회차, 스테이지)`** 순이다 —
회차가 위고, 같은 회차 안에서 스테이지로 가른다. 서버 RPC 를 고쳐야 한다.

## 4. 구현 순서

1. **세이브** — `difficultyTier`(0=쉬움). 기본값 있는 호환 필드라 **스키마 18 유지**.
2. **설정** — `run_config.json → difficultyTiers`: 회차별 체력·공격·보상 배율.
3. **진행 상한** — 스테이지가 `roadmap.finalStage` 를 넘지 않게. 앱·서버 양쪽.
4. **전환 UI** — 1000 클리어 시 안내 + 진입 버튼.
5. **표기** — `progressLabel(tier, stage)`; 홈·랭킹.
6. **랭킹 정렬** — `profiles` 에 `tier` 추가, RPC 정렬 키 변경. ⚠️ SQL 필요.
7. **기존 유저 마이그레이션** — 서버가 1000 초과를 1000 으로 접는다.

⚠️ 3·7 은 **서버가 앱보다 먼저** 나가야 한다. 앱만 먼저 나가면 구버전이
1000 초과를 계속 올려 보낸다.
